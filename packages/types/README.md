# @aria/types

Source of truth for every shared TypeScript contract in the Aria ERP suite. Frontend and backend projects import these entities to eliminate drift.

## Layout

- `src/index.ts` — barrel exports for domain namespaces.
- `src/<domain>/**/*.ts` — structured by B2B domains (Asset, CRM, HR, Inventory, Auth, etc.).
- `dist/` — generated by `tsc --build`; never edit manually.

## Daily Runbook

| Task               | Command                                       | Notes                                     |
| ------------------ | --------------------------------------------- | ----------------------------------------- |
| Build declarations | `pnpm --filter @aria/types build`             | Emits ESM + DTS using project references. |
| Type checking      | `pnpm --filter @aria/types exec tsc --noEmit` | Optional quick check while editing.       |
| Test (future)      | `pnpm --filter @aria/types test`              | Stand up once schema tests arrive.        |

## Authoring Guidelines

- Model each domain inside its own namespace (`export namespace Asset { ... }`).
- Export DTOs, enums, filters, and API payload shapes from `src/index.ts` to keep imports consistent.
- Prefer discriminated unions and branded types over primitive unions for clarity.
- Document breaking contract changes in app-level READMEs and PR summaries.

## Agent Alignment

### Simplicity Advocate

- Keep folders shallow and descriptive. Avoid duplicating types already modelled in other namespaces.
- Reuse utility types rather than hand-writing repeated mappings.

### Type Safety Guardian

- Treat this package as the canonical schema. Frontend and backend must import from here instead of `type` declarations inline.
- Add tests (planned) to guard runtime validators against type mismatches.

### Automation Steward

- Ensure `pnpm build` triggers this package build through `turbo.json`. Update outputs if the build emits new artifacts.
- If publishing to npm (future), set up release automation and versioning tied to contract changes.

### Quality Sentinel

- Pair every new contract with fixtures in `packages/types/testing` (to be created) so Vitest/Playwright suites stay aligned.
- Consider JSON schema generation for API docs once the shapes stabilise.

## Maintenance Checklist

- [ ] Run `pnpm build` before committing to verify downstream compilers stay green.
- [ ] Announce breaking contract changes in the PR description with migration notes.
- [ ] Keep `dist/` out of version control; rely on builds instead of hand-editing.
